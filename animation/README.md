# 社区动画工作台

通过平台主页登录，进入 `/animation/`。初始角色、动作参考、任务和成品均为空。

在主页的 AI 模型配置中，为动画模块选择以下接口：

- **视频生成**：必需。支持 `Videos API` 和 `REST / fantasy-v1`。
- **图片抠图**：必需。绑定支持透明背景图片编辑的图片 API，逐帧去除视频背景。
- **支持识图的 LLM**：用于“AI 辅助编写”，结合参考图把动作意图写成具体运动指令，也用于角色图片和动作参考视频分析。直接输入视频提示词时不调用它。

上传角色参考图片，填写动作意图或视频提示词，即可预览并生成。参考图片和动作视频会以实际数据发送到所选 API，不会将服务器文件路径发送给远程模型。生成后，平台始终使用已绑定图片 API [去除背景](API-MATTING.md)，不会因未配置图像模型而静默改用 CPU 抠图。随后导出透明 PNG 帧、预览和精灵图；原视频保留用于重新后处理。灰色服装、发光和半透明边缘仍需人工检查。

批量生产使用平台原生队列。保留同一个批次 ID 重试时，同一用户的每个任务索引对应同一个持久幂等键。新增一批请更换批次 ID。队列对结果未知的提交保持“需要处理”，不会盲目重复计费请求。

全部成员都可查看、下载和使用其他成员的角色、动作、参考图、任务和资产。“显示所有用户的内容”可切换为只看本人。普通成员可编辑和删除自己的内容；管理员可管理他人内容，原作者归属保持不变。借用参考资料生成的任务和结果归提交者，新建档案会复制他人的参考文件，避免删除自己的档案时影响原资料。

任务保存提交账号及当时的模型选择，服务恢复后仍按原账号执行。个人 API 信息只对本人展示，公共成品、JSON 与 ZIP 导出保留创作参数并移除个人连接信息。使用个人 API 的任务仅创建者可原地重试或重新处理背景；其他账号可选用共享参考资料，以自己的模型另建任务。

## 视频 API 契约

`Videos API` 的基础地址通常以 `/v1` 结尾。`POST /videos` 接收 JSON，包括 `model`、`prompt`、`seconds`、`seed` 和 `conditions`（图片/视频参考的 `data:` URL），返回 `{id,status}`；`GET /videos/{id}` 查询状态，`GET /videos/{id}/content` 下载视频。需要供应商或适配网关支持此 JSON 参考输入契约；不自动转换任意厂商的 multipart 视频接口。

`REST / fantasy-v1` 使用 `POST /generate`，请求为 `{kind:"video",model,input:{...}}`。可返回同步 `artifacts`，或返回任务 `id` 并通过 `GET /jobs/{id}` 查询。完成时返回 `artifacts:[{type:"video",url:"..."}]`。视频下载地址必须与所配 API 同源，不跟随重定向。

任务编译时固定视频配置 ID、地址、协议和模型。此后换绑其他配置不会改变已有任务；修改或删除已有任务使用的配置时，任务暂停等待恢复该配置。API 密钥可在原配置中轮换，密钥不会写进任务或成品元数据。

动画服务只接受门户签发的短期身份令牌，数据根目录由 `ANIMATION_DATA_DIR` 设置（默认 `/data/animation`）。API 与 worker 共用独立的 PostgreSQL、Redis 和动画数据目录；无需在社区版启动本地 GPU 模型。
